# راهنمای دو ریست‌کننده نگه‌بانی و بررسی سلامت (Maintenance Watchdogs)

> نسخه ۰.۴ — پایداری ۲۴/۷ برای ماژول‌های M08R / M08 / SIM800

## ۱. فلسفه

ماژول سلولار در کار طولانی‌مدت (چند روز تا چند ماه) ممکن است به مرور کند، هنگ یا ناپایدار شود. به‌جای انتظار برای خرابی، دو **ریست‌کننده مستقل** به‌صورت دوره‌ای ماژول را کاملاً ریست و سپس **سلامت آن را بررسی** می‌کنند.

## ۲. دو بودجه ریست

### ریست‌کننده اول — بودجه زمانی
هر **N دقیقه** (پیش‌فرض: **۱ ساعت = ۳۶۰۰۰۰۰ میلی‌ثانیه**) یک ریست کامل انجام می‌شود.

### ریست‌کننده دوم — بودجه تعداد عملیات
بعد از **N عملیات موفق/کامل** (پیش‌فرض: **۵۰**) یک ریست کامل انجام می‌شود. منظور از عملیات، هر جاب تمام‌شده (ارسال/دریافت پیامک، تماس، USSD، استعلام وضعیت) است.

هر کدام زودتر فعال شوند، ریست انجام می‌شود. بعد از هر ریست، هر دو بودجه از نو شروع می‌شوند.

## ۳. تنظیمات

### کامپایل (`gsm_config.hpp`):

```c
#define GSM_PERIODIC_RESET_MS  3600000 // ریست‌کننده اول (0 = غیرفعال)
#define GSM_OPS_RESET_COUNT    50      // ریست‌کننده دوم (0 = غیرفعال)
#define GSM_WATCHDOG_GRACE_MS  10000   // حداکثر انتظار برای فرصت امن ریست
```

### زمان اجرا:

```cpp
auto& wd = modem.maintenance();
wd.policy().periodic_ms = 30 * 60 * 1000; // هر ۳۰ دقیقه
wd.policy().ops_period  = 200;            // هر ۲۰۰ عملیات
wd.policy().use_power_cycle = false;      // پیش‌فرض: ریست نرم با AT+CFUN=1,1 (true = PWRKEY)
wd.policy().health_check    = true;       // بررسی سلامت بعد از هر ریست
wd.policy().enabled         = true;
```

### فعال‌سازی دستی:

```cpp
modem.maintenance().request_reset(gsm::ResetReason::Manual);
```

## ۴. چه زمانی ریست انجام می‌شود؟

ریست در یک **فرصت امن** انجام می‌شود:
- هیچ تماسی در جریان نیست
- موتور AT بیکار است
- هیچ جابی در حال اجرا نیست

اگر چنین فرصتی تا `grace_ms` (پیش‌فرض ۱۰ ثانیه) پیدا نشود، ریست **اجباری** انجام می‌شود. مهم: جاب‌های **صف‌کشیده‌شده** در طول ریست نگه داشته می‌شوند و بعد از بالا آمدن مودم ادامه پیدا می‌کنند (`full_restart(..., keep_jobs=true)`).

## ۵. بررسی سلامت (Health Check)

بعد از هر ریست (و با دستور دستی)، یک بررسی سلامت چهارمرحله‌ای اجرا می‌شود:

```
AT        ──▶ پاسخ‌گویی پایه ماژول        (at_ok)
AT+CPIN?  ──▶ وضعیت سیم‌کارت              (sim_ok از ModemStatus زنده)
AT+CREG?  ──▶ ثبت در شبکه                 (net_ok از ModemStatus زنده)
AT+CSQ    ──▶ قدرت سیگنال                  (rssi_dbm)
```

> نکته: پاسخ‌های `+CPIN:` و `+CREG:` توسط `UrcRouter` بلعیده می‌شوند و وضعیت زنده `ModemStatus` را به‌روز می‌کنند؛ برای همین verdict سلامت از همان وضعیت زنده خوانده می‌شود.

نتیجه:

```cpp
modem.set_on_health(MaintenanceWatchdog::ReportCb([](void*, const HealthReport& r) {
    if (!r.ok()) {
        // اقدام اضطراری: پیام هشدار، ریست مجدد، ...
    }
}, nullptr));

const HealthReport& h = modem.maintenance().health();
// h.state: Unknown / Checking / Healthy / Unhealthy
// h.at_ok, h.sim_ok, h.net_ok, h.rssi_dbm, h.resets
```

## ۶. جریان کلی

```
tick() هر تیک:
  watchdog.tick(now)                ──▶ آیا بودجه‌ای تمام شده؟
        │ بله
        ▼
  فرصت امن؟ (بدون تماس/جاب)  ──▶ بله ──▶ AT+CFUN=1,1 (یا PWRKEY اگر use_power_cycle)
        │ خیر                              │
        ▼                                  ▼
  صبر تا grace_ms                 boot guard → پروب AT → Ready
  سپس اجباری                             │
                                          ▼
                                 شروع بررسی سلامت (4 پروب)
                                          │
                                          ▼
                                 گزارش HealthReport → کال‌بک + لاگ
```
