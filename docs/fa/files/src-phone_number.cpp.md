# gsm/src/phone_number.cpp

## نقش فایل

پیاده‌سازی `gsm::PhoneNumber`؛ نرمال‌سازی شماره تلفن به قالب E.164 (با پیشوند `+`). ورودی می‌تواند هر شکلی باشد: بین‌المللی (`+98912…`)، داخلی با صفر (`0912…`)، یا بدون صفر (`912…`)؛ خروجی همیشه یک رشته `+`دار معتبر است که مستقیماً در فرمان‌های `ATD` و `AT+CMGS` قابل استفاده است.

## توابع و منطق کلیدی

### `bool PhoneNumber::assign(const char* raw, const char* country_code = "+98")`
مرحله ۱ — استخراج: کاراکترهای غیررقمی حذف می‌شوند؛ فقط یک `+` در ابتدای رشته پذیرفته می‌شود (پرچم `plus`). بافر `digits` با اندازه ثابت `GSM_SMS_NUMBER_BYTES` پر می‌شود؛ ورودی بدون هیچ رقم → `false`.

```cpp
for (const char* p = raw; *p && n + 1u < sizeof(digits); ++p)
{
    if (*p == '+' && n == 0) { plus = true; continue; }
    if (*p >= '0' && *p <= '9') digits[n++] = *p;
}
```

مرحله ۲ — نرمال‌سازی (کد کشور پیش‌فرض `+98` برای ایران):

| ورودی | خروجی |
|---|---|
| با `+` (بین‌المللی) | `+` + ارقام استخراج‌شده |
| بدون `+` ولی با پیشوند کد کشور (`98…`) | `+` + ارقام (تشخیص با `memcmp` پیشوند) |
| با صفر داخلی (`0912…`) | `+98` + ارقام بدون صفر اول |
| سایر (`912…`) | `+98` + ارقام |

نتیجه نهایی با `valid()` (موجود و غیرخالی) سنجیده می‌شود.

## جریان کاری

```text
"09123456789"  ──► digits="09123456789" ──► شروع با '0' ──► "+989123456789"
"+989123456789" ──► plus=true ──────────────────────────► "+989123456789"
"989123456789" ──► بدون '+' ولی پیشوند "98" ───────────► "+989123456789"
"9123456789"   ──► بدون '+/' بدون پیشوند/بدون صفر ─────► "+989123456789"
"abc"          ──► هیچ رقمی ──► false (نامعتبر)
```

## نکات فنی

- **کد کشور قابل‌تغییر:** پارامتر دوم `assign` به‌صورت پیش‌فرض `"+98"` است؛ برای محصولات غیر ایرانی می‌توان کد دیگری داد (با یا بدون `+`).
- **کوتاه‌سازی بی‌صدا:** اگر ارقام بیش از ظرفیت `GSM_SMS_NUMBER_BYTES` (۲۴) باشند، ارقام اضافی در حلقه نادیده گرفته می‌شوند؛ برای شماره‌های واقعی کافی است اما در دیباگ ورودی‌های مخرب به چشم می‌آید.
- **تشخیص پیشوند کشور:** با `memcmp` روی ابتدای ارقام؛ برای شماره‌هایی که با کد کشور شروع شده‌اند ولی `+` ندارند (`98912…`) درست کار می‌کند. شماره‌های کوتاه‌تر از کد کشور (`98…`) به‌اشتباه ممکن است بین‌المللی تفسیر نشوند — الگوریتم عامدانه ساده است.
- **همیشه `+` در خروجی:** `ATD+98912…;` و `AT+CMGS="+98912…"` با این قالب برای اکثر مودم‌ها (و شبکه ایران) معتبر است.
- **بدون heap:** `value_` یک `static_string` عضو کلاس است؛ `printf` داخلی آن با ظرفیت ثابت کار می‌کند.
- **`e164()`** (در هدر) اشاره‌گر به رشته نرمال‌شده برمی‌گرداند که `CallService` و `SmsService` مستقیم در فرمان‌ها `snprintf` می‌کنند.

## ارتباط با سایر فایل‌ها

- `gsm/codec/phone_number.hpp` — تعریف کلاس، `assign`، `e164()`، `valid()`، `clear()`.
- `src/call_service.cpp` — شماره طرف تماس (`peer_`)؛ شماره‌های دریافتی `+CLIP`/`+CLCC` (حتی UCS2) هم از همین فیلتر می‌گذرند.
- `src/sms_service.cpp` — شماره گیرنده (`recipient_`) در `start_send`.
- `src/modem.cpp` — `send_sms` و `dial` مقدار `job.number` را به `assign` می‌سپارند.
- `include/gsm/gsm_config.hpp` — `GSM_SMS_NUMBER_BYTES` (اندازه بافر ارقام).
