# راهنمای کامل مدیریت تماس (Call Supervision)

> نسخه ۰.۴ کتابخانه — سازگار با ماژول های SIM800 و Quectel M08 / **M08R**

## ۱. چرا این بازنویسی انجام شد؟

در نسخه های قبلی سه مشکل جدی در مدیریت تماس وجود داشت:

1. **مرگ صف با ورود تماس**: اگر تماس بین ارسال پیامک ها رخ می داد، صف کارها (JobQueue) برای همیشه متوقف می شد و دیگر هیچ جابی اجرا نمی شد.
2. **عدم تشخیص قطع/رد تماس**: وقتی طرف مقابل تماس را رد می کرد یا جواب نمی داد، کتابخانه متوجه نمی شد و وضعیت تماس برای همیشه روی `Outgoing`/`Incoming` می ماند.
3. **نبود تایم اوت قطع خودکار**: اگر تماسی وصل نمی شد، هیچ وقت به طور خودکار قطع نمی شد.

هر سه مشکل با یک «سرپرستی تماس» (Call Supervision) جدید حل شده اند.

## ۲. معماری جدید

```
                 ┌────────────────────────────────────────────┐
                 │            CallService (v2)                │
                 │                                          │
   Job Queue ───▶│  start_dial / start_answer / start_hangup │──▶ ATD / ATA / ATH
   (مرحله ها)     │                                          │
                 │  monitor() ── هر تیک، مستقل از صف:        │
                 │    ├─ تایمر قطع خودکار (پیش فرض ۲۰ ثانیه)  │
                 │    ├─ پرس وجوی دوره ای +CLCC               │
                 │    └─ تشخیص ناپدید شدن تماس               │
                 │                                          │
   URC Router ──▶│  notify_ring / notify_hangup / notify_busy│
   (RING, NO CARRIER, BUSY, ...)                             │
                 └────────────────────────────────────────────┘
```

نکته کلیدی: `monitor()` در **هر تیک** از `Modem::tick()` صدا زده می شود، حتی وقتی هیچ جاب تماسی در صف نیست. بنابراین ردیابی تماس هرگز به وضعیت صف وابسته نیست.

## ۳. ماشین حالت تماس

```
        dial()                 ATA                 hang_up()
  Idle ────────▶ Dialing ──▶ Outgoing ──▶ Active ───────▶ Releasing ──▶ Idle
   ▲                │            │            │               │
   │     RING/+CLIP │            │            │               │
   │                ▼            │            │               │
   └──────────── Incoming ◀──────┘            │               │
   ▲                │                         │               │
   │     پاسخ ندادن (تایمر)                    │               │
   └────────────────┴─────────────────────────┴───────────────┘
              (هر گذار با CallEndReason گزارش می شود)
```

## ۴. قطع خودکار بعد از ۲۰ ثانیه (قابل تنظیم)

سیاست نگه بانی در `CallPolicy` تعریف شده است:

```cpp
struct CallPolicy {
    uint32_t dial_timeout_ms = 20000; // تماس خروجی: اگر وصل نشد، قطع خودکار
    uint32_t ring_timeout_ms = 20000; // تماس ورودی: اگر جواب داده نشد، رد خودکار
    uint32_t clcc_poll_ms    = 2000;  // فاصله پرس وجوی +CLCC
    bool     auto_hangup     = true;  // کلید اصلی قطع خودکار
};
```

### تنظیم در زمان اجرا:

```cpp
modem.call_policy().dial_timeout_ms = 30000; // ۳۰ ثانیه
modem.call_policy().ring_timeout_ms = 15000; // ۱۵ ثانیه
```

### تنظیم در زمان کامپایل (پیش فرض ها):

```c
#define GSM_CALL_ANSWER_TIMEOUT_MS 20000
#define GSM_CALL_RING_TIMEOUT_MS   20000
#define GSM_CALL_CLCC_POLL_MS      2000
#define GSM_CALL_CLCC_MISSES       2
```

وقتی تایمر منقضی شود:
1. دلیل پایان روی `CallEndReason::Timeout` تنظیم می شود.
2. فرمان قطع (`AT+CHUP` در M08/M08R، `ATH` در SIM800) ارسال می شود.
3. اگر فرمان اصلی جواب ندهد، یک بار `ATH` به عنوان فرمان جایگزین امتحان می شود.
4. وضعیت به `Idle` برمی گردد و کال بک `on_ended` صدا زده می شود.

## ۵. تشخیص رد تماس / بی جوابی (حتی وقتی ماژول چیزی نمی گوید)

ماژول M08R گاهی هیچ کدام از URCهای پایان تماس (`NO CARRIER`، `BUSY`، `NO ANSWER`) را نمی فرستد. برای همین یک **شبکه ایمنی +CLCC** وجود دارد:

- هر `clcc_poll_ms` (پیش فرض ۲ ثانیه) یک `AT+CLCC` ارسال می شود.
- اگر تماسی در فهرست باشد (`stat=0` فعال، `2/3` در حال شماره گیری، `4/5` ورودی) وضعیت تماس به روز می شود — پاسخ گرفتن تماس (`stat=0`) هم از همین جا تشخیص داده می شود.
- اگر فهرست خالی باشد و تماس «قبلاً دیده شده باشد» یا فعال باشد یا به اندازه کافی قدیمی باشد، بعد از `GSM_CALL_CLCC_MISSES` (پیش فرض ۲) بار خالی، تماس «مرده» اعلام و خط فعالانه آزاد می شود.

نتیجه: رد شدن تماس یا بی جوابی حداکثر چند ثانیه بعد تشخیص داده می شود؛ تایمر ۲۰ ثانیه ای هم به عنوان مرز نهایی عمل می کند.

### دلیل پایان تماس (CallEndReason)

| مقدار | معنی |
|---|---|
| `LocalHangup` | خودمان قطع کردیم |
| `RemoteHangup` | طرف مقابل قطع کرد |
| `Busy` | اشغال بود (BUSY) |
| `NoAnswer` | جواب نداد |
| `NoCarrier` | NO CARRIER |
| `NoDialtone` | NO DIALTONE |
| `Timeout` | تایمر قطع خودکار فعال شد |
| `Error` | خطای دیگر |

دریافت دلیل:

```cpp
modem.set_on_call_ended(CallService::Ended([](void*, CallEndReason r) {
    printf("call ended: %s\n", to_string(r));
}, nullptr));
```

## ۶. گیت تماس — حل مشکل مرگ صف

قانون جدید و ساده:

> **وقتی تماسی در جریان است (Dialing/Outgoing/Incoming/Active/Releasing)، جاب های غیرتماسی اجرا نمی شوند و نگه داشته می شوند. به محض پایان تماس، صف از همان جا ادامه پیدا می کند.**

- جاب های `CallDial`، `CallAnswer` و `CallHangup` (اضطراری) همیشه از گیت عبور می کنند.
- اگر تماس ورودی **وسط ارسال پیامک** برسد، جاب در حال اجرا با `ESC` به صورت امن لغو و برای اجرای مجدد علامت گذاری می شود (`deferred`) — بدون اینکه از بودجه تلاش مجدد (`attempts`) کم شود. این دقیقاً همان جایی است که M08R قبلاً هنگ می کرد و «پیام خالی» می فرستاد.
- جابی که سرویسش حاضر به شروع نشود، چند بار تلاش و سپس با کد خطای `kErrJobStalled` تمام می شود — صف دیگر **هرگز** نمی ایستد.

## ۷. پشتیبانی از M08R

یک `DeviceTraits` اختصاصی به نام `kQuectelM08R` اضافه شده است:

```cpp
static Modem modem(uart, clock, kQuectelM08R, &power);
```

تفاوت با `kQuectelM08`: فیلد `clcc_authoritative = true` — یعنی پرس وجوی +CLCC منبع اصلی حقیقت برای وضعیت تماس است و نباید به URCهای پایان تماس تکیه کرد.
