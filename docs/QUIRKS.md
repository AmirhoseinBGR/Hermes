# درس هایی که از لاگ های خودت گرفتیم (و در کد قفل شده اند)

## 1. با `CSCS="UCS2"` شماره هم باید UCS2 باشد
```
AT+CSCS="UCS2"            OK
AT+CMGS="+989037744527"   +CMS ERROR: 3518   ← شماره ASCII
AT+CMGS="002B0039...3237" >                  ← همان شماره، UCS2-hex
```
کد: `DeviceTraits::ucs2_recipient_required` + `codec::ascii_to_ucs2_hex()` در
`SmsStep::SendHeader`.

## 2. قبل از Ctrl+Z نباید CRLF بفرستی
```
"0633064406270645\r\n" + 1A  → +CMS ERROR: 520
"0633064406270645"    + 1A  → +CMGS: 3   OK
```
کد: `AtEngine::write_raw()` هرگز CRLF اضافه نمی کند؛ فقط `write_ctrl_z()`.

## 3. اگر در حالت prompt گیر کنی، ماژول تا ESC نخورد جواب نمی دهد
```
AT+CMGS="..."   >
"0633..."  (بدون 1A)
at              +CME ERROR: 58
```
کد: `abort()` و هر خطای مرحله ی payload یک `0x1B` (ESC) می فرستد تا از data-entry
بیرون بیاید.

## 4. ترتیب امن ارسال
`AT+CMGF=1` → `AT+CSCS="UCS2"` → `AT+CSMP=...` → `AT+CPMS=...` → `AT+CMGS`.
در لاگ تو با `AT+CSMP=17,71,0,25` و هم با `17,0,8,0` پیام رسید؛ چون عامل اصلی خرابی
موارد ۱ و ۲ بود. پیش فرض SIM800 را روی همان `17,71,0,25` که خودت تست کردی گذاشتم و
برای M08 روی `17,167,0,8` (استاندارد UCS2). هر دو در `DeviceTraits` قابل تغییرند:
اگر روی سیم کارت/شبکه ی دیگری نتیجه فرق کرد، فقط همان یک رشته را عوض کن.

## 5. بنر بوت و URCها قابل اعتماد نیستند
`DY` (نسخه ی بریده ی `RDY`)، `Call Ready`، `SMS Ready`، `+CPIN: READY` همه در
`UrcRouter` هندل می شوند؛ اما ماشین حالت منتظر آن ها نمی ماند و خودش با `AT` پروب می کند.

## 6. تماس
`ATD09037744527;` (سمی کولن = صوتی) کار می کند؛ `AYD...` تایپی بود. قطع تماس در
SIM800 با `ATH` و در M08 با `AT+CHUP` است → `DeviceTraits::hangup_cmd`.

## 7. echo
لاگ تو echo روشن دارد. `ATE0` در bootstrap خاموشش می کند و پارسر هم مقاوم است
(خط برابر با فرمان ارسالی دور ریخته می شود).

## ۸. درس‌های M08R (v0.4)

### پایان تماس بی‌صدا
M08R ممکن است هیچ‌کدام از `NO CARRIER` / `BUSY` / `NO ANSWER` را هنگام رد یا بی‌جوابی
تماس نفرستد. راه‌حل: پرس‌وجوی دوره‌ای `AT+CLCC` به‌عنوان منبع حقیقت
(`DeviceTraits::clcc_authoritative = true` در `kQuectelM08R`) + تایمر قطع خودکار.

### هنگ و ارسال پیام خالی
ارسال متن‌های بلند یا ارسال در میانه عملیات دیگر، ماژول را به حالت prompt/داده گیر
می‌اندازد و گاهی پیام خالی می‌فرستد. راه‌حل‌ها (همه در کد):
- گارد سخت‌گیرانه طول پیام (`GSM_SMS_MAX_CHARS` پیش‌فرض ۶۰ کاراکتر)
- گیت تماس: هیچ ارسالی در حین تماس شروع نمی‌شود
- لغو امن با `ESC` (0x1B) اگر تماس ورودی وسط payload برسد
- ریست‌های دوره‌ای نگه‌بانی (`docs/WATCHDOG.md`)

### قطع تماس
فرمان قطع M08R: `AT+CHUP`. اگر جواب ندهد، `ATH` به‌عنوان فرمان جایگزین ارسال می‌شود
(`CallStep::HangupFallback`).

### `NORMAL POWER DOWN` وسط روشن‌شدن (لاگ کلید K)
PWRKEY روی M08/M08R/SIM800 **toggle** است: همان پولس اگر ماژول روشن باشد خاموشش می‌کند
و `NORMAL POWER DOWN` می‌فرستد (گاهی چند ثانیه دیر، حتی بعد از اینکه `AT` هنوز `OK`
داده چون خاموشی آنی نیست). اگر این URC را همیشه `enter(Off)` کنیم، دستگاه در `off`
می‌ماند در حالی که ماژول ممکن است همان لحظه دوباره روشن شده باشد — یا برعکس، پولس
اول آن را خاموش کرده و پولس دوم (روشن کردن) هرگز زده نمی‌شود.

کد:
- حین `PowerPulsing`/`Booting` این URC یعنی «خاموش شد» → پولس بعدی برای روشن کردن.
- بعد از `AT`/`RDY` موفق، تا `GSM_POWERDOWN_IGNORE_MS` آن را URC کهنه می‌داند و
  `Off` نمی‌شود.
- `AtEngine::execute` دیگر line reader را پاک نمی‌کند تا `NORMAL POWER DO` + `WN`
  وسط پروب `AT` از بین نرود.
- شروع `power_cycle` بافر RX را `discard` می‌کند تا باقی‌مانده‌ی سیکل قبلی نشت نکند.
