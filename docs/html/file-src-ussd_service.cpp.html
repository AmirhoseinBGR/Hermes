gsm/src/ussd_service.cpp

نقش فایل

پیاده سازی gsm::UssdService؛ سرویس کدهای USSD (مثل استعلام موجودی) با فرمان AT+CUSD. متن خروجی همیشه به هگز UCS2 کدبندی می شود، پاسخ شبکه به صورت URC ناخواسته (+CUSD:) دریافت و با توجه به dcs (یا بو کردن محتوا) به UTF-8 برگردانده می شود. نسخه فعلی «تعاملی» نیست: هر پاسخی (حتی درخواست ورودی بیشتر شبکه با m=1) با AT+CUSD=2 بسته می شود؛ مسیر جلسه باز (SessionOpen/send_reply) در کد حاضر است ولی غیرفعال شده است.

توابع و منطق کلیدی

توابع متنی

to_string(UssdStep) → "cusd-enable" | "cusd-send" | "cusd-reply" | "wait-cusd-urc" | "session-open" | "cusd-end" (+ "idle"/"done").

توابع ایستای کمکی (anonymous namespace)

  • encode_ussd_text(text, out, cap, dcs) — تبدیل UTF-8 → هگز UCS2 با codec::utf8_to_ucs2_hex و مقداردهی dcs = 15. (کامنت داخل کد تأکید می کند با dcs=15 هم کار می کند چون payload ذاتاً UCS2 hex است.)
  • build_cusd_command(text, cmd, cap) — ساخت فرمان کامل و رد در صورت شکست رمزنگاری یا بریده شدن:
std::snprintf(cmd, cmd_cap, "AT+CUSD=1,\"%s\",%u", payload, dcs);
return n > 0 && static_cast<uint16_t>(n) < cmd_cap;   // truncation check
  • decode_ussd_text(raw, dcs, out) (قالبی/template) — رمزگشایی پاسخ: dcs == 72 → UCS2، dcs == 15 → خام، نامشخص → looks_like_ucs2_hex؛ یک تور ایمنی هم دارد: حتی اگر dcs بگوید خام، اگر payload آشکارا هگز UCS2 باشد UCS2 رمزگشایی می شود (مودم هایی با dcs گزارش شده غلط).

const char* UssdService::default_balance_code(Operator op)

کد پیش فرض استعلام موجودی اپراتورهای ایرانی: Irancell → 1411#، MCI → 14011#، RighTel و ناشناخته → *140#. (از StatusService::detect_operator تغذیه می شود.)

شروع/کنترل جلسه

  • **start_query(const char* ussd_code)** — شروع استعلام؛ کد در code_ ذخیره، report_ ریست و به گام SetUssdMode می رود.
  • start_balance_query(Operator) — نسخه ساده شده با کد پیش فرض.
  • **send_reply(const char* text)** — ادامه جلسه تعاملی (فقط وقتی session_open_)؛ در نسخه فعلی عملاً غیرقابل دسترس است چون session_open_ هرگز true نمی شود.
  • end_session() — بستن مؤدبانه جلسه با AT+CUSD=2 (گام EndSession).
  • cancel() — لغو: ابتدا AT+CUSD=2 خام (بدون فرمان AT ثبت شده) نوشته می شود تا جلسه شبکه بسته شود، سپس at_.abort() و complete(Aborted, -1).

void UssdService::pump() — ماشین گام ها

  • SetUssdMode — دو فراخوانی پشت سرهم execute دارد (یکی از نکات مهم این نسخه، پایین تر):
case UssdStep::SetUssdMode:
    // AT+CUSD=1 enables presentation of USSD responses
    issued_ = at_.execute("AT+CUSD=2", 1000, this);
    issued_ = at_.execute("AT+CSCS=\"UCS2\"", 1000, this);
    return;
  • SendQuery / SendReply — ساخت فرمان با build_cusd_command؛ در شکست رمزنگاری complete(Aborted, -2)؛ وگرنه AT+CUSD=1,"<hex>",15 با timeout ۱۰s.
  • WaitUrc — انتظار برای +CUSD شبکه با مهلت GSM_AT_USSD_TIMEOUT (۱۰s)؛ در timeout، ابتدا AT+CUSD=2 خام نوشته و سپس complete(Timeout, -1).
  • EndSession — AT+CUSD=2 با timeout ۵s.

void UssdService::on_line(...) / notify_cusd(const char* line)

هر خط +CUSD: (چه از URC و چه پاسخ فرمان) به notify_cusd می رود. ساختار: +CUSD: <m>,"<str>",<dcs>:

  1. استخراج m (کد وضعیت) و dcs با csv_field.
  2. رمزگشایی payload با decode_ussd_text به report_.response؛ report_.status_code = m.
  3. اگر در گام انتظار نباشیم (SendQuery/SendReply/WaitUrc)، پاسخ ناخواسته نادیده گرفته می شود (رویداد ثبت ولی کامل نمی شود).
  4. m == 1 (شبکه ورودی بیشتر می خواهد): در این نسخه جلسه بسته و complete(Ok, 0) می شود — مسیر SessionOpen/on_done_ کامنت شده است.
  5. سایر مقادیر (0 موفقیت، 2 قطع توسط شبکه و …): AT+CUSD=2 خام + complete(Ok, m).

void UssdService::on_final(const AtResult& res)

  • نتیجه «ول شده» (stray): اگر گام Idle یا SessionOpen باشد نادیده گرفته می شود (پاسخ URC زودتر از OK فرمان رسیده و تکلیف را روشن کرده است).
  • خطا → complete(res.status, res.code).
  • SetUssdMode موفق → SendQuery.
  • SendQuery/SendReply موفق → WaitUrc (ثبت wait_start_).
  • EndSession موفق → AT+CUSD=2 خام + complete(Ok, 0).

نکات فنی

  • رفتار SetUssdMode (نکته مهم این نسخه): دو execute پشت سرهم داده می شود در حالی که AtEngine فقط یک فرمان در پرواز می پذیرد؛ فراخوانی دوم (وقتی اولی هنوز تمام نشده) false برمی گرداند و issued_ را false می کند. عملاً فقط AT+CUSD=2 به مودم می رود و فرمان AT+CSCS="UCS2" در این مسیر ارسال نمی شود (و اگر pump دوباره صدا زده شود، executeهای بعدی هم تا پایان فرمان اول رد می شوند). خوشبختانه bootstrap مودم (kBoot در modem.cpp) از قبل AT+CSCS="UCS2" را اجرا کرده و payload همیشه هگز UCS2 است؛ اما ناسازگاری کامنت (AT+CUSD=1) با کد (AT+CUSD=2) هم قابل توجه است — کد فعلی عملاً «بستن جلسه» می فرستد.
  • AT+CUSD=2 خام در چند مسیر: در cancel، timeout WaitUrc، m==1 و پایان EndSession نوشته می شود؛ چون این مسیرها «فرمان AT ثبت شده» ندارند، از write_raw استفاده شده تا ماشین گام ها به هم نریزد.
  • کدبندی همیشه UCS2: برخلاف SMS (که GSM7/UCS2 انتخابی است)، کدها و پاسخ های USSD با dcs=15 و payload هگز UCS2 رد و بدل می شوند؛ برای متن فارسی پاسخ ها ضروری است.
  • کد خطای -2: شکست رمزنگاری خروجی (متن نامعتبر UTF-8 یا کمبود بافر) با complete(Aborted, -2) گزارش می شود؛ این کد داخلی سرویس است نه CME/CMS.
  • پاسخ های ناخواسته: +CUSD ممکن است خارج از درخواست ما بیاید (مثلاً پیامک تعاملی شبکه)؛ شرط گام در notify_cusd جلوی کامل شدن کاذب را می گیرد ولی report_.response با آخرین مقدار به روز می شود.
  • ظرفیت ها: بافرهای raw/payload با GSM_USSD_RESPONSE_BYTES (۵۱۲) و GSM_CMD_MAX (۲۵۶) محدودند؛ build_cusd_command بریده شدن را صریح رد می کند.
  • بدون heap: همه رشته ها (code_، report_.response) از نوع static_string عضو کلاس اند.
