gsm/src/sms_service.cpp

نقش فایل

پیاده سازی gsm::SmsService؛ ماشین وضعیت چندمرحله ای برای ارسال، خواندن، اسکن و حذف پیامک در حالت متنی (AT+CMGF=1). سرویس تنظیمات جلسه (متن بودن، charset، پارامترهای CSMP، مخزن پیامک) را کش می کند تا فرمان های تکراری نفرستد، رمزنگاری UCS2/GSM7 را خودکار انتخاب می کند، و در نسخه v0.4 یک «محافظ سخت گیرانه طول متن خروجی» دارد: متن های بلندتر از max_chars (پیش فرض ۶۰ نویسه UTF-8) همان اول کار با کد خطای kErrSmsTooLong رد می شوند تا مودم های خانواده M08R که با payload بزرگ هنگ می کنند یا پیامک خالی می فرستند، از ریشه در امان بمانند.

uint16_t SmsService::count_chars(const char* utf8) — (ایستا)

تعداد «نقاط کد» UTF-8 را می شمارد (چیزی که کاربر به عنوان کاراکتر می بیند)، نه بایت ها:

for (const unsigned char* p = ...; *p; ++p)
    if ((*p & 0xC0) != 0x80) ++n; // count lead bytes only

فقط بایت های آغازین (lead bytes) شمرده می شوند؛ بایت های ادامه (continuation) با ماسک 10xxxxxx حذف می شوند. این همان متریکی است که max_chars با آن مقایسه می شود.

bool SmsService::start_send(const char number, const char utf8_text, SmsEncoding enc)

شروع ارسال. ترتیب اعتبارسنجی:

  1. اگر سرویس مشغول باشد → false.
  2. محافظ طول (v0.4): اگر max_chars_ != 0 و count_chars(utf8_text) > max_chars_ → لاگ خطا، result_ = AtResult{AtStatus::Error, kErrSmsTooLong} و false.
  3. شماره گیرنده باید با PhoneNumber::assign معتبر شود.
  4. انتخاب رمزنگاری: Auto → default_enc_؛ اگر GSM7 انتخاب شده باشد ولی متن غیر-ASCII باشد، با هشدار به UCS2 ارتقا داده می شود.
  5. گزارش ارسال (SmsSendReport) ریست و به گام SetTextMode می رود.

bool SmsService::start_read(int16_t index, bool delete_after) / start_scan_unread() / start_delete_index(int16_t) / start_delete_read()

ورودی های دیگر سرویس. start_read همیشه UCS2 می خواند؛ start_scan_unread شمارنده pending_count_ را صفر می کند؛ نسخه های حذف مستقیم به گام DeleteIndex/DeleteRead می پرند.

void SmsService::queue_index(int16_t index)

ایندکس پیامک خوانده نشده را در بافر pending_ (حداکثر GSM_SMS_INBOX_SLOTS = 4) صف می کند.

void SmsService::cancel() / fail(...) / complete()

  • cancel — لغو ESC-safe: at_.abort() (ارسال ESC اگر در پرامپت CMGS باشیم)، نتیجه Aborted.
  • fail(st, code) — ثبت نتیجه در result_ و report_.result، بازگشت به Idle و باطل سازی جلسه با session_.invalidate()؛ چون بعد از خطا وضعیت charset/پرامپت مودم ممکن است نامشخص باشد و کش جلسه نباید به حافظه اش اعتماد کند.
  • complete — نتیجه موفق Ok.

void SmsService::pump()

حلقه ای با حداکثر ۸ پله advance_step()؛ گام هایی که به لطف کش جلسه فوراً skip می شوند در همان فراخوانی زنجیر می خورند بدون اینکه نوبت tick بعدی منتظر بمانند:

for (uint8_t guard = 0; guard < 8; ++guard)
{
    const SmsStep before = step_;
    advance_step();
    if (issued_ || !active() || step_ == before) return;
}

void SmsService::advance_step() — ماشین گام ها

مسیر مشترک تنظیمات (با کش جلسه):

گامفرمانشرط skip
SetTextModeAT+CMGF=1session_.text_mode
SetCharsetAT+CSCS="UCS2" یا "GSM"session_.charset برابر مقدار مطلوب
SetCsmptraits_.csmp_ucs2 / traits_.csmp_gsmsession_.csmp_ucs2 هم فاز و charset شناخته شده
SetStoragetraits_.storage_cmdsession_.storage_ready یا بدون دستور مخزن

سپس انشعاب بر اساس هدف: target_index_ >= 0 → ReadMessage؛ گیرنده نامعتبر → ListUnread؛ در غیر این صورت → SendHeader.

مرحله SendHeader: شماره مقصد در صورت نیاز دستگاه (traits_.ucs2_recipient_required) با codec::ascii_to_ucs2_hex به هگز UCS2 تبدیل می شود، سپس:

std::snprintf(cmd, sizeof(cmd), "AT+CMGS=\"%s\"", dest);
req.expect_prompt = true;                 // wait for '>' prompt
req.timeout_ms    = traits_.prompt_timeout_ms;

مرحله WritePayload: متن UCS2 (با utf8_to_ucs2_hex) یا خام نوشته می شود، بلافاصله at_.write_ctrl_z() پایان payload را اعلام می کند و با at_.await_final(traits_.send_timeout_ms, this) منتظر +CMGS: / OK می ماند. در شکست رمزنگاری، ابتدا write_escape() و سپس fail اجرا می شود.

مراحل خواندن/حذف: AT+CMGL="REC UNREAD" (۱۵s)، AT+CMGR=%d (۵s)، AT+CMGD=%d (۵s) و AT+CMGD=1,1 (یا AT+CMGD=1 بسته به traits_.supports_cmgd_delete_all).

void SmsService::on_prompt()

دیدن پرامپت > مودم: اگر در SendHeader باشیم یعنی مودم آماده دریافت payload است → گام WritePayload.

void SmsService::parse_cmgr_header(const char line) / store_body(const char line)

هدر +CMGR: (تک پیام) و +CMGL: (فهرست) با ایندکس فیلد متفاوت پارس می شوند (فهرست یک فیلد ایندکس اضافه دارد). شماره فرستنده اگر هگز UCS2 به نظر برسد (looks_like_ucs2_hex) رمزگشایی می شود. بدنه پیام در خط بعدی با store_body ذخیره و رمزنگاری واقعی (UCS2 یا GSM7) با بو کردن محتوا تشخیص داده می شود.

void SmsService::on_line(const char* line, uint16_t len)

  • +CMGS: <mr> → شماره مرجع ارسال در report_.reference.
  • +CMGR: / +CMGL: → parse_cmgr_header.
  • +CPMS: نادیده گرفته می شود (وضعیت مخزن را StatusService مدیریت می کند).
  • خط بدنه (وقتی expect_body_) → store_body؛ در حالت ListUnread هر پیام بلافاصله با queue_index + on_received_(last_) تحویل داده می شود.

void SmsService::on_final(const AtResult& res)

در هر نتیجه غیرموفق اگر در فاز payload باشیم (WritePayload/WaitAck) ابتدا at_.write_escape() ارسال می شود تا مودم از حالت ورود داده درنیاید، سپس fail. در موفقیت، پرچم های جلسه (text_mode، charset، csmp_ucs2، storage_ready) ثبت و زنجیره ادامه می یابد؛ پس از SetStorage دوباره به همان گام برمی گردد تا انشعاب نهایی (ارسال/خواندن/فهرست) انتخاب شود. SendHeader بدون دریافت پرامپت → fail. WaitAck موفق → complete() با لاگ sent, ref=%d. در ReadMessage اگر delete_after_ تنظیم باشد، به طور خودکار به DeleteIndex زنجیر می شود.

نکات فنی

  • max_chars دو لایه اجرا می شود: هم در Modem::send_sms (رد قبل از ورود به صف) و هم در SmsService::start_send (رد هنگام اجرا). مقدار پیش فرض GSM_SMS_MAX_CHARS = 60 با هدف حاشیه امن زیر سقف ۷۰ نویسه یک SMS UCS2 تک بخشی انتخاب شده؛ با set_max_chars (دستور کنسولی smsmax) یا مقدار ۰ (غیرفعال) قابل تنظیم است.
  • شمارش «نویسه» نه «بایت»: متن فارسی ۶۰ نویسه ای ممکن است ۱۲۰ بایت باشد؛ count_chars بر مبنای نقاط کد UTF-8 تصمیم می گیرد.
  • رفتار fail: چون ممکن است مودم در وضعیت نیمه کاره (مثلاً پرامپت CMGS) رها شده باشد، جلسه کاملاً باطل می شود تا گام های تنظیمی دوباره و بدون اتکا به کش ارسال شوند.
  • pump زنجیره ای: گام های skip شونده حداکثر ۸ پله در یک نوبت جلو می روند؛ این تأخیر tick را حذف می کند ولی جلوی حلقه بی نهایت را هم می گیرد.
  • await_final به جای execute: در فاز payload هیچ فرمان جدیدی ارسال نمی شود؛ فقط نتیجه نهایی (OK/+CMGS) انتظار کشیده می شود. این از تداخل با guard-time موتور AT هم جلوگیری می کند.
  • بدون heap: بافرهای موقت (dest، hex) همگی آرایه های ثابت با اندازه های GSM_SMS_TEXT_BYTES / GSM_SMS_NUMBER_BYTES هستند.
  • kErrSmsTooLong = -100: کد خطای داخلی کتابخانه (نه کد CME/CMS) و در JobResult قابل تشخیص است؛ Modem::finish_job چنین خطاهای سیاستی را retry نمی کند.
