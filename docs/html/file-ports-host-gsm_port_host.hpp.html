gsm/ports/host/gsm_port_host.hpp

نقش فایل

این فایل «پُرت میزبان» (Host Port) برای اجرای کتابخانه ی GSM روی کامپیوتر (بدون سخت افزار واقعی مودم) است. هدف اصلی اش تست و شبیه سازی است: به جای UART واقعی، بافرهای نرم افزاری می سازد که تست می تواند داده «تزریق» (inject) کند و فرستاده شده ها را بازرسی کند. زمان سنج و کنترل تغذیه هم به صورت مصنوعی/شمارنده ای پیاده شده اند تا تست ها قطعی (deterministic) باشند.

ساختارها/توابع کلیدی

  • template <uint16_t Size = 2048> class HostUart final : public hal::IUart

UART شبیه سازی شده با بافر حلقه ای (RingBuffer<Size>) برای RX و یک آرایه ی char برای TX.

  • uint16_t write(const uint8_t* data, uint16_t len) — بایت ها را در بافر tx_ می ریزد (به صورت رشته ی null-terminated) و len را برمی گرداند.
  • uint16_t read(uint8_t* out, uint16_t max) — تا max بایت از بافر RX (rx_.pop) برمی دارد.
  • uint16_t available() — تعداد بایت های موجود در بافر RX (rx_.size()).
  • void drain_rx() — بافر RX را خالی می کند (rx_.clear()).
  • void inject(const char* text) — رشته ای را به عنوان داده ی «دریافتی از مودم» وارد بافر RX می کند (برای شبیه سازی پاسخ مودم).
  • const char* tx() const — دسترسی به بافر ارسالی (برای بازرسی دستورات صادرشده توسط موتور).
  • void clear_tx() — بافر ارسالی را پاک می کند.
  • class HostClock final : public hal::IClock

زمان سنج مصنوعی با عضو عمومی uint32_t now.

  • uint32_t millis() — مقدار now را برمی گرداند؛ تست مقدار now را جلو می برد تا زمان را کنترل کند.
  • class HostPowerControl final : public hal::IPowerControl

شمارنده ی پالس تغذیه برای تشخیص ریست/پاورسایکل سخت افزاری در تست.

  • void power_key(bool asserted) — اگر asserted باشد pulse_count را یکی زیاد می کند.
  • uint32_t pulse_count — تعداد دفعات فشردن کلید تغذیه (برای اثبات اینکه watchdog سخت افزار را ریست کرده).

جریان کاری

  1. تست (tests/host_smoke.cpp) نمونه های HostUart، HostClock و HostPowerControl می سازد و به Modem می دهد.
  2. تست با advance(ms) مقدار clock_.now را جلو می برد و modem.tick() را صدا می زند تا موتور AT پیش برود.
  3. تست با uart.inject("OK\r\n") پاسخ های ساختگی مودم را وارد می کند و با uart.tx() / tx_has(needle) بررسی می کند که موتور چه دستوراتی فرستاده است.
  4. HostPowerControl.pulse_count نشان می دهد که آیا watchdog در شرایط خطای متوالی، پاورسایکل سخت افزاری انجام داده است.

نکات فنی

  • HostUart یک قالب (template) با اندازه ی پیش فرض 2048 است؛ اندازه ی بافر RX و TX یکسان است.
  • write همیشه len را برمی گرداند (حتی اگر بافر TX پر شود)؛ این برای سادگی تست است و بازگشت واقعی خروجی سریال را تضمین نمی کند.
  • بافر TX به صورت رشته ی '\0'-terminated نگه داشته می شود تا بتوان با strstr (در tx_has) جست وجو کرد.
  • HostClock.now عمومی است تا تست بتواند مستقیماً زمان را دستکاری کند (بدون وقفه ی واقعی).
  • HostPowerControl فقط power_key را پیاده می کند؛ reset از پیش فرض رابط (IPowerControl) استفاده می کند.
  • هیچ تخصیص پویا (dynamic allocation) یا استثنایی به کار نرفته؛ با -fno-exceptions -fno-rtti سازگار است.
  • std::strlen/std::memcpy از <cstring> استفاده شده؛ برخلاف پُرت های embedded، اینجا STL مجاز است چون هدف تست میزبان است.

ارتباط با سایر فایل ها

  • gsm/hal/hal.hpp — رابط های IUart/IClock/IPowerControl که اینجا پیاده سازی می شوند.
  • gsm/util/ring_buffer.hpp — RingBuffer که بافر RX از آن ساخته شده.
  • gsm/tests/host_smoke.cpp — تنها مصرف کننده ی این پُرت؛ تمام سناریوهای تست (طول پیامک، نظارت تماس، watchdog، بازیابی SIM و…) از طریق همین شبیه ساز اجرا می شوند.
  • gsm/CMakeLists.txt — با گزینه ی GSM_BUILD_TESTS پوشه ی ports/host را به include path اضافه می کند.
  • در کنار ports/arduino/ و ports/stm32/ قرار می گیرد؛ هر سه یک رابط HAL را برای محیط متفاوت فراهم می کنند.
