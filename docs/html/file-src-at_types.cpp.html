gsm/src/at_types.cpp

نقش فایل

پیاده‌سازی توابع کمکی متنی برای انواع نتیجه فرمان‌های AT: تبدیل AtStatus به رشته قابل‌خواندن برای لاگ، و جدول‌های «راهنمای خطا» برای کدهای +CMS ERROR و +CME ERROR. این فایل هیچ منطق اجرایی ندارد و صرفاً پل ارتباطی بین کدهای عددی مودم و انسان (لاگ/کنسول) است.

const char* to_string(AtStatus s)

جریان کاری

این فایل state-less است؛ در AtEngine::tick هنگام دیدن +CME ERROR / +CMS ERROR فراخوانی می‌شود:

AtEngine::tick ──► classify_final() ──► finish(status, code)
                          │
                          └─► kLog.warn("CMS %d: %s", code, cms_error_hint(code))

نکات فنی

  • کد ۵۲۰ (CMS): نشانه کلاسیک اشتباه در فاز payload پیامک است — ارسال CRLF قبل از Ctrl+Z باعث می‌شود مودم payload را خراب تفسیر کند. SmsService برای همین متن را بدون واسطه و فقط با write_ctrl_z() پایان می‌دهد.
  • کد 3518 (CMS): وقتی AT+CSCS="UCS2" فعال است و شماره مقصد UCS2-encode نشده باشد رخ می‌دهد؛ SmsService::advance_step در مرحله SendHeader با traits_.ucs2_recipient_required این را پیشگیری می‌کند.
  • کد ۵۸ (CME): معروف به گیر کردن مودم در پرامپت ورود داده؛ راه‌حل کتابخانه write_escape() در AtEngine::abort و timeoutهای expect_prompt است.
  • همه رشته‌های خروجی ثابت (static const) هستند؛ بازگشت اشاره‌گر کاملاً امن و بدون تخصیص حافظه است.
  • جدول‌ها «راهنما» هستند نه منطق کنترلی؛ هیچ‌کدام از کدها بر تصمیم‌گیری FSM تأثیر ندارند و فقط برای خوانایی لاگ به کار می‌روند.

ارتباط با سایر فایل‌ها

  • gsm/core/at_types.hpp — تعریف AtStatus، AtResult و ثابت‌های خطای کتابخانه‌ای (kErrSmsTooLong = -100، kErrCallTimeout = -101، kErrJobStalled = -102).
  • src/at_engine.cpp — مصرف‌کننده اصلی این توابع در لاگ نتایج نهایی.
  • src/cli.cpp — to_string(AtStatus) در نمایش نتیجه دستور at <cmd> و رویدادهای [JOB#…].
