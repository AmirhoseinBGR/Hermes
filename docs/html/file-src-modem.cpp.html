gsm/src/modem.cpp

نقش فایل

پیاده‌سازی gsm::Modem؛ هسته مرکزی کتابخانه که همه چیز را کنار هم می‌نشاند: ماشین وضعیت بوت/ثبت شبکه، صف jobها (JobQueue)، سرویس‌های SMS/تماس/وضعیت/USSD، مسیریاب URC، سگ نگهبان صنعتی و watchdog نگهداری. این فایل در v0.4 چهار قابلیت کلیدی گرفته است: گیت تماس (نگه‌داشتن jobهای غیر-تماسی بدون از‌بین‌رفتن صف)، رفع گیرکردن pump_services (jobهایی که start نمی‌شوند بعد از چند تلاش fail می‌شوند به‌جای قفل‌کردن صف)، preempt_for_call (لغو ESC-safe ارسال پیامک در جریان هنگام ورود تماس) و maintenance_service / full_restart (reset کامل زمان‌بندی‌شده که صف jobها را حفظ می‌کند).

توابع و منطق کلیدی

جدول بوت kBoot

ترتیب فرمان‌های راه‌اندازی بعد از ثبت شبکه:

{"ATE0", 1000, false},      {"AT+CMEE=2", 1000, true},   // optional
{"AT+CLIP=1", 1000, true},  {"AT+CNMI=2,1,0,0,0", 1000, true},
{"AT+CMGF=1", 1000, false}, {"AT+CSCS=\"UCS2\"", 1000, false},
{nullptr, 0, false},   // → traits_.csmp_ucs2
{nullptr, 0, false},   // → traits_.storage_cmd

دو مورد nullptr در tick از DeviceTraits پر می‌شوند؛ اگر دستگاهی چنین فرمانی نداشته باشد، همان لحظه نتیجه موفق مصنوعی می‌گیرد و جلو می‌رود. فرمان‌های non-optional در صورت شکست FSM را به Fault می‌برند.

to_string(ModemState)

"off" | "booting" | "pwrkey-pulsing" | "waiting-reg" | "configuring" | "ready" | "working" | "ringing" | "in-call" | "sim-missing" | "fault".

چرخه حیات: begin() / reset() / power_cycle() / full_restart(...)

  • begin() — صفر کردن شمارنده‌های بازیابی، ثبت زمان در watchdog (on_reset_started)، ورود به Booting.
  • reset() — at_.abort() + stop_all(false) + begin() (نرم، صف پاک می‌شود).
  • power_cycle() — پالس PWRKEY در صورت وجود IPowerControl، سپس reset().
  • full_restart(bool hardware, bool keep_jobs) (v0.4): راه‌اندازی مجدد کامل با انتخاب سیاست صف:
at_.abort();
if (keep_jobs) {
    // فقط job در حال اجرا لغو و نهایی می‌شود؛ صف انتظار دست‌نخورده می‌ماند
    if (current_.state == JobState::Running) { svc->cancel(); finish_job({Aborted,-1}); }
} else {
    stop_all(false);   // پاک‌سازی کامل صف
}
if (hardware && power_) power_->power_key(true), power_->power_key(false);
begin();

گیت تماس (v0.4)

bool Modem::is_call_job(JobKind kind);   // CallDial | CallAnswer | CallHangup
bool Modem::call_gate() const            // call_.state() != CallState::Idle

هر job غیر-تماسی وقتی تماسی در جریان است (engaged) نگه‌داشته می‌شود — نه لغو، نه حذف؛ صف بعد از پایان تماس ادامه می‌یابد.

void Modem::preempt_for_call() (v0.4)

هنگام ورود تماس (URC RING/+CLIP) روی job در حال اجرا صدا زده می‌شود:

if (current_.state != JobState::Running || is_call_job(current_.kind)) return;
IService* svc = service_for(current_.kind);
if (svc) svc->cancel();              // ESC-safe abort of any pending SMS payload
current_.deferred = true;
current_.state    = JobState::Queued; // بازگشت به صف برای اجرای مجدد بعد از تماس

به‌لطف SmsService::cancel → at_.abort() → write_escape()، مودمی که در پرامپت CMGS گیر کرده بدون خراب‌شدن payload از حالت داده خارج می‌شود. پرچم deferred در start_job باعث می‌شود بودجه تلاش (attempts) برای این اجرای مجدد مصرف نشود.

void Modem::maintenance_service() (v0.4)

پل بین MaintenanceWatchdog و اجرای واقعی reset:

watchdog_.tick(clock_.millis());
// پنجره امن: بدون تماس، بدون فرمان AT در پرواز، بدون job جاری
const bool safe = call_.state() == CallState::Idle && at_.idle() && current_.kind == JobKind::None;
const bool forced = hal::elapsed(now, maintenance_since_, watchdog_.policy().grace_ms);
if (!safe && !forced) return;
full_restart(hardware_power_cycle, /*keep_jobs*/ true);

اگر پنجره امن پیدا نشود، حداکثر به اندازه grace_ms (پیش‌فرض ۱۰s) صبر می‌کند و بعد reset «اجباری» انجام می‌شود. در هر دو حالت صف jobها حفظ می‌شود.

صف‌بندی: enqueue و متدهای عمومی

enqueue(Job&, JobCallback) شماره یکتای JobId (از ۱، بدون صفر)، زمان ورود و وضعیت Queued ثبت می‌کند؛ صف پُر → kInvalidJob. متدهای راحتی: send_sms (با محافظ طول — پایین‌تر)، read_sms، scan_sms، delete_read_sms، dial، answer (urgent)، hang_up (urgent)، refresh_status، ussd، check_balance (کد پیش‌فرض اپراتور ایرانی از UssdService::default_balance_code).

JobId Modem::send_sms(...) — محافظ سخت‌گیرانه طول (v0.4)

قبل از ورود به صف، متن با SmsService::count_chars شمرده و با sms_.max_chars() (پیش‌فرض GSM_SMS_MAX_CHARS = 60) مقایسه می‌شود؛ در صورت تجاوز، job بلافاصله Failed با kErrSmsTooLong به callback گزارش و kInvalidJob برمی‌گردد (بدون اشغال صف):

if (limit && chars > limit) {
    job.state  = JobState::Failed;
    job.result = AtResult{AtStatus::Error, kErrSmsTooLong};
    cb(job); on_job_(job);
    return kInvalidJob;
}

bool Modem::start_job(Job&)

اعلام شروع به سرویس متناظر (service_for)؛ برای job برگشتی از preempt_for_call بودجه تلاش مصرف نمی‌شود (deferred)، وگرنه attempts++. در موفقیت: JobState::Running + enter(Working).

void Modem::finish_job(const AtResult&) — سیاست تلاش مجدد

  • SmsSend شماره مرجع (reference) و UssdQuery پاسخ (ussd_response) را در job کپی می‌کند.
  • timeout پیاپی شمرده می‌شود؛ از GSM_CONSECUTIVE_TIMEOUTS_RESET (۳) بیشتر → check_watchdog() (بازیابی سخت‌افزاری).
  • سیاست‌های رد (kErrSmsTooLong / kErrJobStalled) و لغو (Aborted) هرگز retry نمی‌شوند.
  • خطای retry‌پذیر تا max_attempts (برای SMS دو) دوباره به صف برمی‌گردد (JobState::Queued).
  • پس از نهایی‌شدن: watchdog_.note_operation() (تغذیه بودجه عملیات watchdog)، وضعیت نهایی Succeeded/Cancelled/Failed، فراخوانی callback و on_job_، و تعیین وضعیت FSM (InCall/Ringing/Ready).

void Modem::on_line(...) / on_final(...)

  • در WaitingRegistration پاسخ +CREG?/+CGREG پارس و با ثبت شبکه به Configuring می‌رویم (timeout ثبت: GSM_REGISTRATION_TIMEOUT = 45s → Fault).
  • در SimMissing خط +CPIN: READY یعنی بازگشت سیم‌کارت → WaitingRegistration.
  • on_final در Booting: موفق → WaitingRegistration؛ سه پاسخ ناموفق AT → PowerPulsing (حداکثر ۲ پالس PWRKEY) و سپس Fault.
  • در Configuring: نتیجه هر گام بوت در پرچم‌های session_ (echo_off، text_mode، charset، csmp_ucs2، storage_ready) ثبت می‌شود تا سرویس‌ها فرمان تکراری نفرستند؛ پایان جدول → Ready + refresh_status().

void Modem::pump_services() — رفع گیرکردن صف (v0.4)

سه شاخه:

1) job جاری Running؟ ──► svc->pump()  یا  finish_job(svc->result())
2) job جاری Queued؟
      ├─ گیت تماس و job غیر-تماسی؟ ──► return (نگه‌داشته می‌شود؛ صف زنده است)
      ├─ start_job موفق؟ ──► شروع اجرا (start_failures_ = 0)
      └─ شکست: ++start_failures_ تا GSM_JOB_START_RETRIES (3)
             ──► fail با نتیجه سرویس یا kErrJobStalled؛ صف دوباره آزاد می‌شود
3) job جاری None؟ ──► queue_.pop → گیت تماس؟ (بازگشت به Queued) : start_job

قبل از این اصلاح، jobی که سرویسش (مثلاً به‌دلیل state ناسازگار) حاضر به شروع نبود برای همیشه جلوی صف را می‌گرفت؛ حالا حداکثر ۳ تلاش و سپس kErrJobStalled (-102) و ادامه کار صف.

void Modem::pump_housekeeping()

کارهای دوره‌ای (فقط وقتی گیت تماس باز است): full_sweep_ms (وضعیت کامل)، signal_ms (CSQ)، sms_scan_ms (اسکن پیامک‌های خوانده‌نشده)، cleanup_ms (حذف پیامک‌های خوانده‌شده اگر مخزن پر باشد).

void Modem::check_watchdog() — سگ نگهبان صنعتی

  1. پاک‌سازی jobهای کهنه: purge_stale(now, GSM_JOB_MAX_AGE_MS=45s)؛ jobهای معلق مانده بیش از ۴۵ ثانیه با callback لغو حذف می‌شوند.
  2. بازیابی پس از timeout پیاپی (≥۳): stop_all + power_cycle() (یا reset() بدون PWRKEY).
  3. گیرکردگی در Fault/SimMissing بیش از GSM_HARDWARE_REBOOT_TIMEOUT_MS (۹۰s): power-cycle کامل سخت‌افزاری.

void Modem::handle_sim_recovery()

ماشین بازیابی سیم‌کارت در وضعیت SimMissing:

  • هر GSM_SIM_RETRY_INTERVAL_MS (۱۰s): پروب AT+CPIN?.
  • هر GSM_CFUN_CYCLE_INTERVAL_MS (۲۵s): چرخه AT+CFUN=0 (فاز ۱) سپس AT+CFUN=1 (فاز ۲) برای راه‌اندازی مجدد لایه RF/SIM.

void Modem::tick() — حلقه اصلی

هر بار فراخوانی در حلقه اپلیکیشن:

at_.tick()                    ← پردازش بایت‌ها/خط‌ها/نتایج
flush_cancelled()             ← تحویل callback های لغوشده
check_watchdog()              ← پاک‌سازی کهنه + بازیابی خطای صنعتی
call_.monitor(now, at_.idle()) + call_.pump()   ← سرپرستی تماس (مستقل از صف)
maintenance_service()         ← بازنشاننده‌های دوگانه watchdog
┌─ FSM ────────────────────────────────────────────────┐
│ Off/Fault        → return                            │
│ SimMissing       → handle_sim_recovery()             │
│ Booting          → پروب "AT"                         │
│ PowerPulsing     → پالس PWRKEY → Booting             │
│ WaitingRegistration → "AT+CREG?" هر 2s (timeout 45s) │
│ Configuring      → اجرای جدول kBoot                  │
└──────────────────────────────────────────────────────┘
if (at_.idle()):
    stat_.pump() / pump_services()
    به‌روزرسانی وضعیت FSM (InCall/Ringing/Ready) + pump_housekeeping()
    watchdog_.pump(...)      ← پروب‌های سلامت فقط در idle کامل

نکات فنی

  • گیت تماس ≠ توقف صف: jobهای متوقف‌شده با deferred علامت می‌خورند و بعد از تماس بدون مصرف بودجه تلاش از سر گرفته می‌شوند؛ callback هرگز گم نمی‌شود.
  • kErrJobStalled = -102: کد داخلی برای «job قابل شروع نبود»؛ مثل kErrSmsTooLong retry نمی‌شود تا صف هرگز wedge نشود.
  • preempt_for_call فقط job جاری را لغو می‌کند نه صف را؛ ترکیب با گیت تماس یعنی «تماس وسط ارسال پیامک» هم امن است (payload با ESC لغو می‌شود و بعداً دوباره ارسال می‌شود).
  • full_restart(keep_jobs=true) با reset کامل watchdog سازگار است: budgetهای زمانی/عملیاتی صفر می‌شوند ولی درخواست‌های کاربر از بین نمی‌روند.
  • session_ (SessionState): کش وضعیت مودم (echo/CMGF/CSCS/CSMP/CPMS) که با هر reset یا fail سرویس SMS باطل می‌شود؛ از فرمان‌های تنظیمی تکراری جلوگیری می‌کند.
  • ترتیب در tick مهم است: سرپرستی تماس قبل از FSM و pump_services صدا زده می‌شود تا تایمرهای قطع/+CLCC همیشه به‌موقع برسند حتی وقتی صف شلوغ است.
  • شماره‌گذاری JobId: از ۱ شروع می‌شود و صفر (kInvalidJob) هرگز برنمی‌گردد؛ پس از سرریز uint16_t به ۱ می‌پرد.
  • GSM_JOB_MAX_AGE_MS = 45000: جلوی انباشت صف وقتی مودم آفلاین است را می‌گیرد؛ jobهای کهنه با حالت Cancelled به callback گزارش می‌شوند.
