gsm/library.json

نقش فایل

متادیتای بسته برای PlatformIO (و ابزارهای مشابه مدیریت کتابخانه). این فایل نام، نسخه، توضیحات، کلیدواژه ها، چارچوب ها/پلتفرم های پشتیبانی شده و پرچم های ساخت کتابخانه ی gsm-modem را تعریف می کند. این همان «شناسنامه ی» کتابخانه است که به ابزار بیرونی می گوید چگونه آن را بسازد و در چه محیط هایی قابل استفاده است.

ساختارها/توابع کلیدی

این فایل JSON است و ساختار تابعی ندارد؛ کلیدهای اصلی:

  • "name": "gsm-modem" — نام بسته.
  • "version": "0.4.0" — نسخه ی فعلی (v0.4، نسخه ای که کنسول CLI را به هسته منتقل کرد).
  • "description" — توصیف مختصر: درایور غیرمسدودکننده ی SIM800 / Quectel M08/M08R با C++17؛ شامل هسته ی AT، نظارت تماس با قطع خودکار، نگهبان سخت گیرانه ی طول پیامک، واچ داگ دوگانه ی نگهداری با بررسی سلامت، صف شغل، پیامک متنی UCS2، کنسول CLI تعاملی؛ بدون STL و بدون تخصیص پویا.
  • "keywords" — برچسب های جست وجو: sim800, quectel, m08, m08r, gsm, sms, ucs2, stm32, arduino, cli, watchdog, call.
  • "frameworks" — stm32cube, arduino, * (هر چارچوب دیگر).
  • "platforms" — ststm32, atmelavr, espressif32, native.
  • "build" — پیکربندی ساخت:
  • "srcDir": "src" — پوشه ی منبع.
  • "includeDir": "include" — پوشه ی سرصفحه ها.
  • "flags" — پرچم های کامپایل: -std=gnu++17, -fno-exceptions, -fno-rtti.

جریان کاری

  1. PlatformIO (یا ابزار مشابه) library.json را می خواند تا نام/نسخه ی بسته را بشناسد.
  2. بر اساس "platforms" و "frameworks" سازگاری با محیط هدف بررسی می شود.
  3. با "srcDir"/"includeDir" ساختار پوشه برای کامپایل مشخص می شود.
  4. پرچم های "build.flags" هنگام کامپایل اعمال می شوند (C++17 بدون استثنا/RTTI).
  5. کتابخانه به صورت خودکار در پروژه ی مصرف کننده گنجانده و ساخته می شود.

نکات فنی

  • "version": "0.4.0" با تغییر معماری v0.4 هم خوان است: کنسول تعاملی از اپلیکیشن به هسته (gsm/cli/) منتقل شد.
  • توضیحات بر «No STL, no dynamic allocation» تأکید دارد؛ با پرچم های -fno-exceptions -fno-rtti هم راستا است.
  • "platforms" شامل native است تا تست میزبان (host_smoke) هم پشتیبانی شود.
  • "frameworks" با * به هر چارچوب دیگری اجازه ی استفاده می دهد (فقط قرارداد HAL رعایت شود).
  • پرچم -std=gnu++17 (به جای c++17) افزونه های GNU را مجاز می کند؛ با CMake که CMAKE_CXX_STANDARD 17 دارد هم ساز است.
  • این متادیتا با gsm/CMakeLists.txt هم راستا است: هر دو C++17 و بدون استثنا/RTTI.

ارتباط با سایر فایل ها

  • gsm/CMakeLists.txt — معادل CMake این پیکربندی (همان استاندارد و پرچم ها).
  • gsm/src/ و gsm/include/ — پوشه هایی که srcDir/includeDir به آن ها اشاره می کنند.
  • gsm/ports/ — پُرت های stm32cube/arduino/native که در "platforms"/"frameworks" منعکس شده اند.
  • gsm/tests/host_smoke.cpp — تست میزبان که با پلتفرم native سازگار است.
  • توضیحات به قابلیت هایی اشاره دارد که در فایل های هسته پیاده شده اند: sms_service, call_service, job_queue, watchdog, cli.
